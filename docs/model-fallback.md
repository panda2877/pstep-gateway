# 模型 Fallback 机制

本文档详细说明 pstep-gateway 如何实现主备模型的自动故障转移，以及智能恢复策略。

## 概述

当主模型不可用（限流、宕机、错误）时，pstep-gateway 自动切换到配置的 fallback 模型，确保服务连续性。同时具备智能恢复机制，在主模型恢复后逐步恢复使用。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         Model Fallback 架构                                  │
└─────────────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────────┐
│                         Router                    │                       │
│  ┌────────────────────────────────────────────┐   │                       │
│  │            build_chain()                    │   │                       │
│  │  ┌─────────┐  ┌─────────┐  ┌─────────┐     │   │                       │
│  │  │Primary  │→ │Fallback1│→ │Fallback2│ →...│   │                       │
│  │  └────┬────┘  └─────────┘  └─────────┘     │   │                       │
│  │       │                                     │   │                       │
│  │       ▼                                     │   │                       │
│  │  ┌────────────────────────────────────┐     │   │                       │
│  │  │     ThawTracker (冻结/解冻)        │     │   │                       │
│  │  │  ┌─────────────────────────────┐   │     │   │                       │
│  │  │  │ 连续失败 N 次 → 冻结主模型   │   │     │   │                       │
│  │  │  │ 定时探测 → 解冻主模型        │   │     │   │                       │
│  │  │  └─────────────────────────────┘   │     │   │                       │
│  │  └────────────────────────────────────┘     │   │                       │
│  └────────────────────────────────────────────┘   │                       │
└──────────────────────────────────────────────────────────────────────────┘
```

## 核心组件

### 1. 路由链构建

**文件**: [src/router.rs](../src/router.rs)

```rust
fn build_chain(&self, model_name: &str) -> Result<Vec<String>, String> {
    let route = self.config.models.get(model_name)?;
    
    let mut chain = vec![model_name.to_string()];
    
    // 支持 fallback_chain (新格式)
    chain.extend(route.fallback_chain.clone());
    
    // 兼容 legacy fallback 字段
    if chain.len() == 1 {
        if let Some(legacy_fallback) = &route.fallback {
            if !route.fallback_chain.contains(legacy_fallback) {
                chain.push(legacy_fallback.clone());
            }
        }
    }
    
    Ok(chain)
}
```

### 2. ThawTracker 冻结/解冻跟踪

**文件**: [src/thaw.rs](../src/thaw.rs)

负责追踪模型健康状态，执行冻结和解冻逻辑。

## 配置示例

### 基础 Fallback

```yaml
models:
  claude-sonnet:
    upstream: anthropic-main
    model: "claude-3-5-sonnet-20241022"
    fallback: gpt-4o  # 单一 fallback
```

### 多级 Fallback 链

```yaml
models:
  claude-sonnet:
    upstream: anthropic-main
    model: "claude-3-5-sonnet-20241022"
    fallback_chain:
      - gpt-4o-mini    # 第一 fallback
      - gpt-4o         # 第二 fallback
```

### 配置字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `upstream` | string | 主模型使用的上游配置名 |
| `model` | string | 上游实际的模型 ID |
| `fallback` | string | 单一 fallback 模型名（兼容旧格式） |
| `fallback_chain` | array | 多级 fallback 列表（新格式，推荐） |

## 冻结/解冻机制

### 为什么要冻结？

当主模型持续失败时（如 API 限流或宕机），如果每次请求都先尝试主模型再 fallback：
1. 每次请求都会产生一次失败延迟
2. 可能加剧上游限流
3. 浪费客户端等待时间

**冻结机制**：连续失败 N 次后，暂时跳过主模型，直接使用 fallback。

### 冻结流程

```
连续失败 3 次
      │
      ▼
┌─────────────────────────────────────────────┐
│  check_and_freeze(upstream, model)          │
│                                             │
│  if failure_count >= FREEZE_THRESHOLD {     │
│      is_frozen = true;                      │
│      frozen_at = now();                     │
│  }                                          │
└─────────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────────────┐
│  主模型被冻结                                │
│  is_frozen(primary) = true                 │
│                                             │
│  后续请求直接跳过主模型:                     │
│  chain = ["claude-sonnet(frozen)",          │
│           "gpt-4o-mini", "gpt-4o"]          │
│  实际请求: gpt-4o-mini                       │
└─────────────────────────────────────────────┘
```

### 解冻流程（智能恢复）

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  定时检查: try_thaw()                                                        │
│                                                                             │
│  每隔一定时间（默认 30 秒）检查冻结状态                                        │
└─────────────────────────────────────────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│  解冻条件检查                                                                │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │ 1. 冻结时间 >= 解冻冷却期 (默认 60 秒)?                               │   │
│  │ 2. 请求是否在活跃期?                                                 │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│  如果满足条件:                                                               │
│                                                                             │
│  - 清除 is_frozen 标志                                                      │
│  - 下次请求重新尝试主模型                                                    │
│  - 如果主模型成功 → 恢复正常                                                 │
│  - 如果主模型失败 → 重新冻结并延长冷却期                                      │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 解冻参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `FREEZE_THRESHOLD` | 3 | 连续失败次数达到此值则冻结 |
| `THAW_INTERVAL` | 30s | 检查解冻的时间间隔 |
| `THAW_COOLDOWN` | 60s | 冻结后需要等待的时间 |
| `ACTIVITY_WINDOW` | 5min | 无请求视为非活跃期 |

## 响应头标识

当发生 failover 时，响应会包含特殊头：

```http
X-Pstep-Failover: true
```

客户端可以据此判断是否使用了 fallback 模型：

```rust
let response = await fetch('/v1/chat/completions', options);
if (response.headers.get('X-Pstep-Failover') === 'true') {
    console.log('使用了 fallback 模型，服务可能不稳定');
}
```

## 用量跟踪

Failover 情况下，用量记录仍然准确：

```rust
self.usage_tracker.record(UsageRecord {
    model: model_name.to_string(),      // 客户端请求的模型名
    upstream: current_upstream.clone(), // 实际使用的上游
    prompt_tokens: usage.prompt_tokens,
    completion_tokens: usage.completion_tokens,
    total_tokens: usage.prompt_tokens + usage.completion_tokens,
    success: true,
    latency_ms: start.elapsed().as_millis() as u64,
});
```

**注意**: `model` 字段记录的是客户端请求的模型名（如 `claude-sonnet`），而非实际使用的 fallback 模型（如 `gpt-4o`）。这确保了用量统计与计费逻辑的一致性。
